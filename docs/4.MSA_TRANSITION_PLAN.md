# MSA 전환 및 프로젝트 구조화 계획 (MSA Transition Plan)

## 1. 개요
본 문서는 기존 단일 프로젝트(Monolith) 환경에서 `commerce-backend`라는 루트 프로젝트 하위의 **멀티 모듈(Multi-Module)** 기반 마이크로서비스 아키텍처(MSA)로 전환하기 위한 구조 및 계획을 정의합니다.

## 2. 타겟 프로젝트 구조 (Target Structure)
Gradle 멀티 모듈 방식을 채택하여 공통 코드를 재사용하고 빌드 의존성을 효율적으로 관리합니다.

```text
commerce-backend (Root Project)
├── build.gradle (Root Build Script: 공통 플러그인 및 버전 관리)
├── settings.gradle (Module Include 설정)
│
├── commerce-core (Module: Common Library)
│   ├── 설명: 모든 마이크로서비스가 공유하는 핵심 라이브러리
│   └── 내용: 공통 DTO, Exception, Utility, JWT Parsing Logic, Feign Client 설정 등
│
├── service-gateway (Module: API Gateway)
│   ├── 설명: 외부 트래픽의 진입점 (Ingress)
│   └── 기술: Spring Cloud Gateway, Netty
│
├── service-user (Module: User Domain)
│   ├── 설명: 사용자 관리 및 소셜 그래프(팔로우) 처리
│   └── DB: MySQL (Users Table), Redis (Session)
│
├── service-post (Module: Content Domain)
│   ├── 설명: 게시물 및 미디어, 댓글 처리
│   └── DB: MySQL (Posts Table), MongoDB (Comments)
│
├── service-feed (Module: Feed System)
│   ├── 설명: 뉴스 피드 생성(Fan-out) 및 조회
│   └── 기술: Kafka Consumer, Redis (Timeline Cache)
│
└── service-search (Module: Search Engine)
    ├── 설명: 사용자 및 해시태그 검색
    └── 기술: Elasticsearch
```

## 3. 상세 진행 단계 (Milestones)

### Step 1: 프로젝트 구조 재편 (Project Restructuring)
*   [ ] 루트 `settings.gradle` 수정: 하위 모듈(`commerce-core`, `service-user` 등) 정의.
*   [ ] 루트 `build.gradle` 수정: `subprojects` 블록을 활용한 공통 의존성(Lombok, Test 등) 및 Spring Boot 버전(3.2.x) 관리.
*   [ ] 하위 모듈 디렉토리 생성 및 각각의 `build.gradle` 작성.

### Step 2: 공통 모듈 구현 (Core Module Implementation)
*   [ ] `commerce-core` 모듈 구현.
*   [ ] 표준 응답 포맷(`ApiResponse`), 공통 예외(`GlobalExceptionHandler`) 클래스 작성.
*   [ ] 멀티 모듈 간 의존성 연결 확인.

### Step 3: 서비스별 스캐폴딩 (Service Scaffolding)
*   [ ] **API Gateway (`service-gateway`)**: 포트 8080 설정, 라우팅 규칙(Routes) 기본 설정.
*   [ ] **User Service (`service-user`)**: 포트 8081 설정, DB 연동(JPA), 도메인 엔티티 생성.
*   [ ] **Post Service (`service-post`)**: 포트 8082 설정.
*   [ ] **Feed Service (`service-feed`)**: 포트 8083 설정.

### Step 4: 핵심 기능 이관 및 구현
*   [ ] `API_SPEC.md` 및 `SCHEMA_DESIGN.md`를 기반으로 각 모듈별 Controller, Service, Repository 구현.
*   [ ] Kafka 연동 설정 및 테스트.

## 4. 기술 표준 및 컨벤션
*   **패키지 구조**: `com.commerce.{module_name}.*` (예: `com.commerce.user.controller`)
*   **빌드 도구**: Gradle (Kotlin DSL 또는 Groovy DSL 통일)
*   **Java Version**: Java 17
*   **Spring Boot**: 3.4.8
